# Pocketch 제품 명세서

## 1. 제품 개요

Pocketch는 한 대의 노트북에서 물건 채집과 캐치 게임을 연속으로 체험하는 현장형 웹게임이다. 관람객이 내장 카메라로 소지품을 촬영하면 브라우저가 배경을 제거하고, 완성된 이미지가 물리 오브젝트로 변환되어 채집 화면에 쌓인다. 같은 이미지 풀은 30초 캐치 게임의 낙하 아이템으로 사용된다.

### 목표

- 촬영한 실물이 즉시 게임 요소가 되는 경험을 제공한다.
- 별도 모바일 기기, 백엔드 또는 운영자 개입 없이 한 기기에서 완결한다.
- 창 크기에 관계없이 검은 배경의 간결한 화면과 안정적인 물리 동작을 유지한다.
- 행사 중 수집한 물건과 점수를 같은 브라우저에 보존한다.

### MVP 제외 범위

- 모바일 컨트롤러와 대형 화면 간 실시간 통신
- 온라인 계정과 서버 랭킹(채집 세션 공유는 2.5절의 옵트인 기능으로 별도 지원)
- 보너스 아이템, 함정, 경품 지급과 관리자 인증
- 배경 음악과 효과음

## 2. 사용자 경험

### 공통 화면

- 기본 배경은 검은색으로 하고 장식은 최소화한다.
- 채집, 게임, 랭킹 모드로 언제든 이동할 수 있는 내비게이션을 제공한다.
- 게임 진행 중 다른 모드로 이동하려 하면 현재 게임이 종료된다는 확인 창을 표시한다.
- 브라우저 크기가 바뀌면 캔버스, 카메라 미리보기, 물리 경계와 UI가 현재 크기에 맞게 재배치된다.
- 주요 버튼은 키보드 포커스와 명확한 포커스 표시를 지원한다.

### 2.1 촬영 및 등록

`물건 추가` 버튼을 누르면 촬영 전용 모달이 열리고, 촬영부터 등록까지 이 모달 안에서 끝난다. 채집 화면과 물리 장면은 모달 뒤에서 그대로 유지된다.

1. 모달을 열면 카메라 권한을 요청한다.
2. 실시간 미리보기에서 물건을 확인하고 촬영한다.
3. 촬영 결과를 미리 보여주고 `재촬영`과 `배경 제거` 중 하나를 선택하게 한다.
4. 배경 제거 단계에서 사용자가 남길 물건을 한 번 터치하며, 처리 중에는 진행 상태를 표시하고 중복 실행을 막는다.
5. 결과 화면에서 투명 배경 이미지를 확인한다.
6. 물건 이름은 필수, 설명은 선택으로 입력받는다.
7. 저장하면 이미지와 메타데이터를 IndexedDB에 기록하고 채집 장면에 즉시 추가하며 모달을 닫는다.

배경 제거는 브라우저에서 수행한다. 터치한 지점을 기준으로 객체 마스크를 생성하고, 해당 처리가 실패할 때는 일반 배경제거 모델로 자동 전환한다. 투명 이미지는 긴 변을 최대 1024px로 축소하고 알파 채널을 유지하는 WebP Blob으로 저장한다. 모달을 취소하거나 ESC·바깥 영역 클릭으로 닫으면 카메라 스트림과 임시 미리보기 이미지를 즉시 폐기한다.

### 2.2 물리 채집 장면

- 새 물건은 화면 상단의 안전한 임의 위치에서 떨어진다.
- 물건은 화면 바닥·좌우 경계 및 다른 물건과 충돌하며 안정된 더미를 만든다.
- 투명 여백을 제거한 이미지 경계를 기준으로 충돌 바디를 생성해 시각적인 겹침을 줄인다.
- 초기 아이템 크기는 대표적인 물건 약 20개가 화면 높이의 75% 부근을 차지하도록 뷰포트 기준으로 계산한다.
- 더미의 최고점이 화면 높이의 25% 선을 넘어, 전체 높이의 75% 이상을 차지하면 축소 단계가 한 번 증가한다.
- 축소 단계가 증가할 때마다 전역 배율을 직전 배율의 70%로 변경한다. 기존 물건과 이후 추가되는 모든 물건에 동일한 누적 배율을 적용한다.
- 기존 물건의 이미지와 충돌 바디를 새 배율로 갱신하고 화면 안쪽에 비례 재배치한 다음 물리가 다시 안정되게 한다.
- 한 번의 추가 작업에서 축소는 한 단계만 수행하며, 안정화 후에도 다음 물건이 임계선을 넘으면 같은 규칙을 반복한다.

#### 포인터 밀치기 물리

- 아이템 상자 안에서 포인터를 움직이면 버튼을 누르지 않아도 이동 경로 가까이에 있는 채집물이 이동 방향으로 밀리며 서로 섞인다.
- 포인터가 상자 안에 있을 때만 반응하며, 상자에 처음 들어온 좌표는 기준점으로만 사용해 갑작스러운 충격을 방지한다.
- 영향 반경과 충격 속도의 최대 크기를 제한해 물건이 화면 밖으로 튕겨 나가거나 물리 계산이 불안정해지지 않게 한다.
- 개별 물건을 직접 누르고 드래그하는 동작과 600ms 길게 눌러 상세 정보를 여는 동작은 그대로 유지한다.

#### 아이템 상세와 삭제

- 아이템을 포인터로 600ms 이상 누르면 상세 모달을 연다.
- 표시 크기가 작아져도 최소 44px 크기의 투명 히트 영역을 유지한다.
- 모달에는 확대 이미지, 이름, 설명과 촬영 시각을 표시한다.
- 삭제는 확인을 받은 뒤 IndexedDB와 현재 물리 장면에서 함께 반영한다.
- 전체 초기화는 별도 버튼과 재확인 절차를 제공하며 물건 데이터와 축소 단계를 초기화한다.

### 2.3 캐치 게임

- 등록된 물건이 없으면 게임 시작 버튼을 비활성화하고 촬영 모드로 안내한다.
- 게임판은 상단 메뉴 아래의 브라우저 공간을 채운다. 시작 전 최대 폭 480px의 성함 입력 모달을 띄우고, Enter 또는 시작 버튼으로 카운트다운을 시작한다. 닫기·Escape는 채집 화면으로 돌아간다.
- 3초 카운트다운 후 30초 게임을 시작한다.
- 저장된 전체 물건 중 하나를 균등하게 무작위 선택하여 화면 상단의 임의 위치에서 낙하시킨다. 같은 물건은 여러 번 등장할 수 있다.
- 플레이어는 방향키 또는 `A/D` 키를 누르는 동안 바구니를 좌우로 움직인다.
- 바구니는 화면 경계를 벗어나지 않으며 키를 동시에 누른 경우 마지막으로 입력된 방향을 사용한다.
- 일반 물건은 100점, 빠른 보너스는 300점·속도 1.12배, 초고속 보너스는 500점·속도 1.25배다. 충돌 시 실제 획득 점수를 표시하며 보너스에는 색 테두리와 점수 배지를 붙인다.
- 일반 아이템은 900ms마다 계속 생성한다. 14·20번째 일반 아이템에는 빠른 보너스, 26·30번째에는 초고속 보너스를 별도로 추가한다. 해당 일반 아이템을 좌우 가장자리 쪽에 배치하고, 반대편 보너스를 화면 위에서 함께 출발시켜 어느 쪽 점수를 노릴지 선택하게 한다.
- 놓친 물건은 점수에 영향을 주지 않으며 게임은 계속된다. 같은 물건에 대한 판정은 한 번만 반영한다.
- 등록된 물건 개수는 낙하 속도나 생성 간격 같은 난이도 계산에 사용하지 않는다. 시작 낙하 속도는 화면 높이 기준 초당 25%이며, 경과 시간(일시정지 제외)에 따라 30초 동안 최대 1.7배까지 점진적으로 빨라진다.
- 남은 시간이 0초가 되면 새 아이템 생성을 중단하고 즉시 결과 화면으로 전환한다.
- 창이 비활성화되거나 숨겨지면 타이머와 물리를 자동 일시정지하고, 돌아오면 안내 후 재개한다. 일시정지 시간은 난이도 경과 시간에도 포함하지 않는다.
- 창 크기가 바뀌어도 점수와 남은 시간은 유지한다.
- 다시 시작하면 점수, 획득 개수, 경과 시간과 낙하 속도가 모두 초기 상태로 돌아간다.

결과 화면에는 성함, 최종 점수, 획득 개수와 `다시하기`, `랭킹 보기`를 제공한다.

### 2.4 랭킹

- 완료된 게임 결과를 IndexedDB에 저장한다.
- 점수 내림차순으로 정렬하고, 동점이면 먼저 기록된 결과를 우선한다.
- 상위 10개 기록의 순위, 성함, 점수와 플레이 시각을 보여준다.
- 랭킹 전체 삭제는 확인 절차를 거쳐 수행한다.

### 2.5 채집 세션 공유 (옵트인)

- 기본값은 기존과 동일하게 완전 로컬·오프라인이다. 소유자가 사이드바에서 `공유 링크 만들기`를 눌러야만 공유가 시작된다.
- 공유를 켜면 이 기기(익명 식별자)를 소유자로 하는 채집 세션이 만들어지고, `?session=` 링크가 발급된다.
- 링크로 접속한 조회자는 실시간으로 갱신되는 채집물을 볼 수 있지만 물건을 추가·수정·삭제할 수 없다. 소유권 검증은 클라이언트 UI와 서버 보안 규칙 양쪽에서 강제한다.
- 소유자의 로컬 IndexedDB와 오프라인 동작이 항상 우선한다. 공유는 별도의 원격 저장소로 물건을 미러링하는 부가 기능이며, 원격 동기화가 실패해도 로컬 채집·게임 흐름에는 영향을 주지 않는다.
- 원본 이미지는 기기에만 남고, 공유본은 용량 제한에 맞춰 별도로 축소 인코딩한 사본만 원격에 올라간다.
- 소유자가 공유를 해제하거나 채집물 전체를 초기화하면 원격 세션과 그 안의 물건도 함께 제거된다.

## 3. 기술 설계

### 애플리케이션 구성

- Vite, React와 TypeScript로 화면, 모달, 폼과 애플리케이션 상태를 구성한다.
- Phaser 3와 Matter Physics로 채집 더미 및 캐치 장면을 구현한다.
- 카메라는 `navigator.mediaDevices.getUserMedia`를 사용한다.
- 배경제거는 클라이언트 측 라이브러리를 사용하며 처리 대상 이미지를 외부 애플리케이션 서버로 전송하지 않는다.
- IndexedDB 접근은 저장소 모듈 한 곳으로 캡슐화하고 스키마 버전을 관리한다.
- 정적 호스팅에서 새로고침할 수 있도록 서버 의존 라우팅 대신 클라이언트 상태 기반 모드 전환을 사용한다. 유일한 예외는 공유 링크로, 부팅 시 `?session=` 쿼리 파라미터 유무만 읽어 읽기 전용 화면으로 분기하며 별도 라우팅 라이브러리나 서버 라우팅은 도입하지 않는다.
- 채집 세션 공유는 Firebase(Firestore + 익명 인증) 무료 플랜을 사용한다. 관련 설정값이 없으면 공유 버튼만 비활성화되고 나머지 기능은 그대로 동작한다.

### 데이터 모델

```ts
interface CollectedItem {
  id: string;
  name: string;
  description: string;
  image: Blob;
  width: number;
  height: number;
  createdAt: string;
}

interface CollectionSettings {
  id: "collection-settings";
  scaleLevel: number;
  globalScale: number;
  sessionId?: string; // 공유가 켜져 있을 때만 존재
}

interface GameResult {
  id: string;
  nickname: string;
  score: number;
  caughtCount: number;
  playedAt: string;
}
```

데이터베이스에는 별도의 스키마 버전을 둔다. `CollectedItem` 삭제 시 이후 게임의 아이템 풀에서도 제외한다. 게임이 시작되면 해당 판에서 사용할 아이템 목록을 스냅샷으로 보관하여 플레이 도중 데이터 변경에 영향을 받지 않게 한다.

### 오류 처리

- 카메라 API 미지원: 지원 브라우저와 실행 조건을 안내한다.
- 권한 거부 또는 카메라 없음: 권한을 다시 허용하는 방법과 재시도 버튼을 제공한다.
- 배경제거 모델 다운로드 또는 처리 실패: 원본을 저장하지 않고 재시도와 취소를 제공한다.
- IndexedDB 읽기 실패: 복구 가능한 안내를 표시하고 데이터 초기화를 사용자가 직접 선택하게 한다.
- 저장 공간 부족: 저장 실패를 알리고 기존 아이템 관리 화면으로 안내한다.
- 이미지 디코딩 실패: 해당 항목만 제외하고 나머지 채집물과 게임은 계속 사용할 수 있게 한다.

## 4. 구현 단계

1. Vite·React·TypeScript 기반 앱과 공통 검은색 반응형 레이아웃을 구성한다.
2. IndexedDB 스키마와 물건·설정·랭킹 저장소를 구현한다.
3. 카메라 촬영, 미리보기, 배경제거와 등록 폼을 연결한다.
4. 물리 채집 장면, 반복 축소 규칙, 상세 모달과 삭제를 구현한다.
5. 30초 캐치 게임, 키보드 조작, 점수와 일시정지를 구현한다.
6. 성함 입력, 결과 저장과 상위 10위 랭킹을 연결한다.
7. 실제 노트북 카메라, 다양한 창 크기와 누적 아이템 환경에서 통합 검증한다.

## 5. 테스트 및 완료 기준

### 자동 테스트

- 물건, 축소 설정과 랭킹의 저장·조회·삭제 및 스키마 복원을 검증한다.
- 필수 이름과 성함의 공백 입력을 거부하는지 확인한다.
- 대표 이미지 18~22개로 첫 번째 축소 임계 조건을 검증한다.
- 축소 단계마다 배율이 `1 → 0.7 → 0.49 → 0.343`으로 누적되는지 확인한다.
- 게임 타이머, 아이템별 점수, 놓친 물건의 무감점과 시간 종료 처리를 검증한다.
- 경과 시간에 따른 낙하 속도 배율이 등록 물건 개수와 무관하게 계산되고 최대치를 넘지 않는지 검증한다.
- 점수 및 기록 시각에 따른 랭킹 정렬과 상위 10개 제한을 검증한다.

### 브라우저 통합 테스트

- 카메라 권한 승인·거부, 재촬영, 처리 실패와 재시도를 확인한다.
- 촬영물을 저장한 뒤 새로고침해 이미지, 메타데이터와 축소 단계가 복원되는지 확인한다.
- 물건들이 화면 밖으로 이탈하거나 눈에 띄게 겹치지 않고 안정되는지 확인한다.
- 길게 누르기, 상세 모달, 개별 삭제와 전체 초기화를 확인한다.
- 게임 중 포커스 상실, 모드 이탈과 창 크기 변경 시 상태가 안전하게 처리되는지 확인한다.
- 새로고침 후에도 랭킹이 유지되고 전체 삭제가 동작하는지 확인한다.
- 공유 링크를 다른 브라우저(또는 시크릿 창)로 열어 조회 전용으로 보이는지, 소유자만 추가·삭제할 수 있는지 확인한다.
- 아이템 상자 안에서 클릭 없이 포인터를 움직일 때 이동 경로 가까이의 물건만 밀리고, 상자 밖의 움직임에는 반응하지 않는지 확인한다.

### 현장 검증

- 최신 Chrome이 설치된 노트북과 내장 카메라에서 전체 흐름을 수행한다.
- 작은 창, 일반 창과 전체 화면에서 촬영 UI 및 게임 경계가 잘리지 않는지 확인한다.
- 최소 100개의 저장 이미지로 물리 프레임, 이미지 메모리와 게임 시작 시간을 점검한다.
- MVP에는 강제 아이템 수 제한을 두지 않되, 성능 저하나 저장 공간 부족을 사용자에게 오류 없이 안내해야 완료로 인정한다.
